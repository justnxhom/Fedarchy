# Asset Clearance Report

Evidence-based review of bundled assets for the first public release of Fedarchy.

*Audit date: 2026-10-11. All findings below were verified against primary sources
(upstream repository, Simple Icons licence text, GitHub API), not inferred from
filenames or appearance.*

---

## 1. Headline finding

**Fedarchy bundles no original assets.** Every binary and media file in the
project is byte-identical to upstream Omarchy:

| Group | Files | Verified identical to upstream |
|---|---|---|
| Theme backgrounds / previews | 159 | **159 / 159** |
| Other media (Plymouth, SDDM, Chromium ext.) | 22 | **22 / 22** |
| Agent SVG marks | 4 | **4 / 4** |
| Icon font | 1 | **1 / 1** (sha256 match) |
| **Total media/binary** | **186** | **186 / 186 (100%)** |

This matters for the clearance decision: the risk is **inherited wholesale from
upstream**, not newly introduced by Fedarchy. Fedarchy's own contributions are
**source and documentation**, which is the strongest category of material to
publish.

## 2. Icon font — `default/fonts/omarchy/omarchy.ttf`

### 2.1 What it is

A 9,972-byte private-use icon font (`family: omarchy`, `foundry: PfEd`) containing
**15 glyphs at U+E900–U+E90E**. It is generated by `bin/omarchy-dev-font`, which
appends monochrome SVG paths from a file or URL into the TTF.

### 2.2 Evidence gathered

| Check | Result |
|---|---|
| Byte-identity vs upstream | **Identical** (sha256 `154c1a11…fda0f5`) |
| Licence file beside the font | **None** — upstream `LICENSE` and `OFL.txt` both HTTP 404 |
| Licence file in Fedarchy | **None** |
| Copyright/licence string inside the TTF binary | **None** — `strings` finds no `copyright`, `licence`, or `trademark` |
| Provenance tracking in the generator | **None** — `omarchy-dev-font add <name> <svg-or-url>` records nothing about licence or origin |
| Glyph usage | **15/15 used**, across **30 menu entries** in `default/omarchy/omarchy-menu.jsonc` |

### 2.3 Per-glyph rights evidence

| Glyph | Brand | Source class | Evidence of redistribution rights |
|---|---|---|---|
| `U+E900` | Omarchy | Upstream's own | **Sufficient** — upstream's own mark, MIT repo |
| `U+E906` `E907` `E90B` `E90D` `E90E` | LM Studio, Ollama, Perplexity, Cursor, Claude | Simple Icons SVG | **Copyright: CC0. Trademark: NOT granted** — see below |
| `U+E90A` | Hermes | **Traced** from a Nous Research desktop icon | **Insufficient** — file carries `Copyright (c) 2025 Nous Research` |
| `U+E908` `E90C` | T3 Code, OpenClaw | **Traced** from raster/favicon artwork | **Insufficient** — README states tracing was used because no official vector exists |
| `U+E901`–`E905`, `E909` | Pi, OpenCode, omp, Grok, Codex/OpenAI, Ori/OpenRouter | Vendor's own website/brand page | **Insufficient** — a published logo is for *brand use*, not a redistribution licence |

**Decisive quote — Simple Icons licence, §4(i) Limitations and Disclaimers:**
> "No trademark or patent rights held by Affirmer are waived, abandoned,
> surrendered, licensed or otherwise affected by this document."

So for the 5 Simple Icons glyphs, copyright in the path data is waived (CC0), but
**trademark is explicitly excluded**. The remaining 8 third-party glyphs have no
evidenced permission at all, and 2 are demonstrably traced with a named
copyright holder.

### 2.4 Conclusion

**Redistribution rights are not established for 14 of 15 glyphs.** This is a
*confirmed evidence gap*, not merely missing paperwork: for the traced glyphs we
have positive evidence that a third party holds rights, and for the Simple Icons
glyphs we have explicit evidence that trademark is not licensed.

### 2.5 Same-class assets found elsewhere

Applying the same standard beyond the font:

| File | Mark | Status |
|---|---|---|
| `shell/plugins/agents/assets/claude.svg` | Anthropic | **Holdback** — brand mark, no evidenced permission |
| `shell/plugins/agents/assets/codex.svg` | OpenAI | **Holdback** — brand mark, no evidenced permission |
| `shell/plugins/agents/assets/codex-light.svg` | OpenAI (light) | **Holdback** — same |
| `shell/plugins/agents/assets/fireworks.svg` | Generic decoration | **Release** — not a brand mark |

The two agent SVGs are the same class of risk as the font glyphs and are held back
with them for consistency.

## 3. Theme backgrounds

### 3.1 Inventory

| Metric | Value |
|---|---|
| Background files | 92 across 22 themes (75 unique filenames) |
| Theme directories | 22 |
| Themes added by Fedarchy | **0** — all 22 exist upstream |
| Upstream themes omitted by Fedarchy | 1 (`starship`) |
| Licence/attribution file inside `themes/` | **None** |
| Upstream `themes/LICENSE`, `themes/nord/LICENSE` | **HTTP 404** |
| Per-file copyright/author metadata | **None found** |

### 3.2 Byte-identity check (full, 4 themes sampled)

| Theme | Files | Identical to upstream | Differing |
|---|---|---|---|
| nord | 4 | 4 | 0 |
| gruvbox | 6 | 6 | 0 |
| tokyo-night | 8 | 8 | 0 |
| retro-82 | 9 | 9 | 0 |
| **Total** | **27** | **27** | **0** |

Fedarchy omits only upstream's `intros/` directories. It introduces no original
backgrounds.

### 3.3 Conclusion

**This is an inherited uncertainty, not a Fedarchy-introduced defect.** Fedarchy
reproduces upstream's content byte-for-byte, so whatever basis upstream relied on
to publish these images is the same basis available here.

However, the requirement is to *"not assume that all inherited upstream
backgrounds are automatically cleared"*, and no per-asset licence was ever
evidenced **upstream either**. This is therefore classified as a
**precautionary holdback-class concern**: not a confirmed legal defect, but an
absence of evidence on 64 MB of material.

**Impact of exclusion: none functionally.** Backgrounds are optional per theme;
`themes/*/backgrounds/` can be absent without breaking `omarchy-theme-set`, the
theme picker, or the shell. The visible effect is that such themes fall back to a
solid or default background.

## 4. Copyright and attribution — the decision you must make

### 4.1 Current state of `LICENSE`

The root `LICENSE`:
- Reproduces the upstream MIT notice **verbatim** (byte-verified against the live
  upstream `LICENSE`; only a trailing newline differs).
- States that no copyright holder has been designated for the Fedora-specific
  modifications.
- **Deliberately invents no holder**, and does **not** assign the changes to DHH.

GitHub's API independently reports upstream `license: MIT`, corroborating this.

### 4.2 What is inherited vs. original (evidence-based)

Measured by comparing this tree against upstream's file list (2,326 files, branch
`quattro`):

| Category | Files | Meaning |
|---|---|---|
| **Shared path with upstream** | 1,076 | Inherited lineage. Sampled 25: **12 byte-identical**, **12 modified** |
| **Fedarchy-only paths** | 117 | Predominantly Fedarchy's own work |

Fedarchy-only paths by area:

| Area | Count | Nature |
|---|---|---|
| `tests/` | 37 | Fedarchy's own regression suites |
| `bin/` | 26 | COPR helpers, Fedora-specific utilities |
| `default/` | 19 | Fedora/DNF-specific templates and bindings |
| `docs/` | 17 | Fedarchy documentation suite |
| `scripts/` | 6 | **The installer** (`install.sh`, `install-components.sh`) and test runner |
| `shell/` | 5 | 3 real files + 2 excluded debris |
| `config/` | 3 | Fedora config |
| root docs | 3 | CHANGELOG, CONTRIBUTING, THIRD_PARTY_NOTICES |
| `themes/` | 1 | `tokyo-night/shell.toml` |

Plus 12 of the 1,076 shared-path files are **modified** by Fedarchy (sampled:
`bin/omarchy-display-text-size`, `shell/plugins/reminders/ReminderFlow.qml`,
`default/hypr/apps/browser.lua`, `README.md`, `AGENTS.md`, `LICENSE`, and others).

### 4.3 The decision required

You must choose **who holds copyright in the Fedora-specific contributions**
(the ~117 Fedarchy-only files plus the ~12+ modified inherited files).

Defensible options:

**Option A — Individual authorship (recommended default).**
Add a second copyright line above the MIT grant:
```
Copyright (c) David Heinemeier Hansson      # inherited Omarchy material
Copyright (c) <year> <Your Name>             # Fedarchy-specific modifications
```
Use this if you wrote the changes personally.

**Option B — Organisation / collective.**
Substitute an organisation or team name as holder.

**Option C — No separate holder (status quo).**
Leave as-is. The MIT grant covers the whole repository, but the *ownership*
question for the modifications stays formally unanswered. Acceptable for a
single-maintainer casual port; weaker for a public release others may fork.

**None of these can be chosen for you.** Naming a holder asserts a legal fact
about who owns the work, and no evidence in the tree establishes it. I have left
the attribution **unchanged**.

## 5. Release options

Pick one. Options A–C differ only in what enters the first public commit.

### Option A — Minimal-risk first release (recommended)

Publish **1,099 files (15.1 MiB)**: all source, tests, docs, configuration,
theme palettes/icon-mappings/editor maps, Plymouth/SDDM theme art, and the
Chromium extension — excluding the 5 holdback files and the 92 theme backgrounds.

- **Loses:** themed backgrounds (92 files, 52.0 MiB — themes fall back to a solid
  colour); 30 menu entries lose their brand icons and render as blank/`.notdef`;
  the agent panel's Claude/Codex marks.
- **Gains:** zero unresolved third-party marks in public history.
- **Reversible:** backgrounds can be added in a later, separately reviewed commit.

### Option B — Full-media release with documented basis

Publish all **1,191 files (67.1 MiB)** including the font and backgrounds, and add a
`NOTICE`-style section stating that media is inherited verbatim from upstream
Omarchy under its MIT licence, with trademark status explicitly disclaimed.

- **Gains:** feature-complete first release.
- **Requires:** you accept the trademark exposure for the 14 traced brand marks.
  This is a decision I cannot make or verify for you.

### Option C — Defer

Publish source-only (no media at all) as a first release, then add media after
you have researched the individual asset rights. Lowest risk, least useful first
release.

### Recommended disposition per asset group

| Asset group | Files | Recommended |
|---|---|---|
| Icon font + traced Hermes SVG | 2 | **Holdback** — confirmed evidence gap |
| Agent brand SVGs (Claude, Codex ×2) | 3 | **Holdback** — same class |

| Theme backgrounds | 92 | **Precaution** — hold back in Option A, or accept in B |

## 6. What this report does not do

- It does **not** modify the font, remove any glyph, or alter any asset.
- It does **not** assert that any licence is invalid — only that permission is
  **not evidenced**.
- It does **not** add a copyright holder or change `LICENSE`.
- It does **not** create a commit, remote, or upload.

A modified font would require testing for rendering, layout and `.notdef`
behaviour before it could be considered usable. That work is a separate,
authorised engineering change.
